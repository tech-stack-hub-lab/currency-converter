# Currency Converter Spoken Presentation

Hello everyone. Today I am going to present my currency converter project. I built this project using HTML, CSS, JavaScript, Bootstrap, and Chart.js. The primary goal was to create a responsive web application that allows users to convert amounts between currencies instantly while also providing local weather information and visual exchange trends. This project is designed to be clean, fast, and easy for users to access on desktop, tablet, or mobile devices.

To start, let me explain the main purpose of the application. The currency converter is a single-page web application that combines several useful tools in one interface. It offers a live conversion feature, a swap function for quickly changing currency direction, a chart to visualize exchange trends, a local weather panel, and a section that shows country-based currency cards in a light and efficient design. The app also includes an expandable About section and a FAQ section, which helps users understand the product better.

Now I will walk you through the project structure. The app is organized into three main files: `index.html` holds the page structure, `assets/css/style.css` contains all the visual styling and responsive rules, and `assets/js/script.js` stores the application logic and API interactions. Additionally, there is a local JSON file at `assets/json/currency.json` that keeps the list of countries and their currency details. This JSON file helps improve performance because it avoids the need to request currency list data from an API every time the page loads.

When I designed the user experience, I focused on a few key user stories. First, the app supports light and dark themes. Users can switch themes using a toggle button, and the chosen theme is stored with `localStorage` so the preference stays even after the page is refreshed. This makes the app more comfortable to use in different lighting environments.

The main conversion feature lets users enter an amount and choose the base currency and the target currency. The form is simple and intuitive: a number input, two select boxes, and a convert button. There is also a swap button that quickly exchanges the selected currencies. This is especially useful when users want to check the reverse conversion immediately. The result is displayed with the converted amount, the exchange rate, and the last updated time. This gives users confidence that the information is current.

For the chart feature, I included a line chart powered by Chart.js. The intention is to help users see how the exchange rate changes over time. The current implementation tracks weekly data in the frontend. It stores conversion points in `localStorage` and uses those points to render the chart. Since the app is still frontend-only, the chart data is limited to the local history available in the browser. The app also plans to support longer historical ranges like monthly, yearly, and five-year trends when a backend proxy is added.

The weather panel is another important part of the interface. It uses the browser’s geolocation API to get the user’s location and then fetches weather information from the OpenWeather API. This includes the weather condition, temperature, and feels-like temperature. The weather panel can be opened and closed by clicking the Local Weather button. It also closes when the user clicks outside the panel, so the interaction feels natural.

Another area I focused on is the country-based currency cards. These cards are generated from local JSON data, which includes details like country name, currency symbol, ISO code, and notes. The cards are loaded in batches to keep the page fast and responsive. Initially only a small set of cards appear, and users can click a Load More button to reveal additional cards. This approach prevents slow load times and improves performance, especially on mobile devices.

Accessibility and responsive design are also central to this project. The page uses semantic HTML tags and ARIA attributes in several places. For example, the chart has proper labels and descriptions to help screen readers understand the content. The forms and buttons are accessible and easy to navigate. I also included responsive CSS rules that adapt the layout and font sizes for smaller screens. The chart container is styled with a responsive aspect ratio, so it scales cleanly on tablets and phones.

While implementing this app, I also handled error conditions to make it robust. If a user enters an invalid amount or leaves the select boxes empty, the app displays a clear message. If the API request fails, the user sees an error and can try again. The country list is loaded from a local JSON file, which also provides a fallback in case the currency API is temporarily unavailable.

One important technical challenge I faced was the CORS limitation for the historical exchange rate API. The chart feature was designed to support different time ranges, including day, week, month, year, and five years. However, when I attempted to call the historical API directly from the browser with an API key, the server rejected the request due to cross-origin restrictions. This is a common security feature that prevents client-side applications from exposing API keys or making certain direct requests. As a result, the current chart implementation uses only weekly data in the frontend as a workaround.

In the future, I plan to solve this challenge by adding a backend proxy. This backend would receive requests from the frontend, add the API key securely on the server side, and forward the request to the exchange rate provider. That way, the browser would no longer need to contact the third-party API directly, avoiding CORS issues and keeping the API key hidden. Once this backend proxy is in place, the chart can be extended to support full historical data ranges, such as month, year, and five years.

Let me explain how the implementation is split across the main files. In `index.html`, the navbar includes links to Home and About, the theme toggle, and the Local Weather control. The header contains the main converter form and the chart area. The converter form uses easy-to-read labels, and the chart has an accessible heading and description. Below the header is the About section, which includes a Read More button. When the user clicks this button, additional text appears, providing more detailed information without cluttering the page.

The `assets/css/style.css` file includes the visual styling for the app. It defines the overall color palette, fonts, buttons, and the layout of the form and cards. I used CSS variables for the main colors, which makes it easier to adjust the theme later. There are also responsive breakpoints to ensure the layout works on smaller screens. For example, the converter form and chart container adjust their sizes and spacing for tablets and phones. I also added specific rules to make the chart container maintain a clean aspect ratio and fill the available width.

The `assets/js/script.js` file contains the core logic. It starts by setting the theme based on `localStorage`. The theme toggle listens for user clicks and updates the page theme and icon accordingly. The weather menu logic toggles the panel and closes it when the user clicks outside. The weather fetch function reads geolocation coordinates and retrieves weather data from OpenWeather. It then updates the DOM with the location name, temperature, and condition text.

The currency conversion logic loads the local JSON file, populates the currency select options, and sets default values. It also initializes the chart and performs the first conversion automatically. When the user changes the input amount or currency selections, the app recalculates the conversion and updates the result. The swap button swaps the selected currency values and retriggers the conversion. All of this happens smoothly in the browser, and the results are displayed immediately.

The chart logic is also included in `script.js`. It initializes a Chart.js line chart with responsive settings. The app saves conversion history into `localStorage` with a timestamp and the rate. The chart uses this locally stored history for rendering. It filters the history based on the selected range, which currently supports weekly data. The chart updates every time a new conversion is made or the chart range changes. This gives users a visual sense of how the exchange rate moves.

The country cards are loaded and rendered using JavaScript as well. The app fetches the JSON file, creates card elements dynamically, and appends them to the page in small batches. Each card shows the currency symbol, country name, currency name, ISO code, and a short note. The Load More button allows users to see more cards without slowing down the page at first load. This approach makes the UI more responsive.

From a testing standpoint, I validated the HTML structure and ensured the page uses semantic tags properly. I also checked the CSS for responsive behavior and consistency. The JavaScript was reviewed to make sure the logic flows correctly, includes error handling, and does not break when the API is unavailable. I did not include automated tests in this version, but the app has been tested manually for key behaviors, including theme toggling, currency conversion, chart refresh, weather fetching, and the Read More interaction.

Now I will talk about future scope and improvements. The first priority is adding a backend proxy to support full historical exchange rate data. This backend will allow the chart to use actual day, month, year, and five-year data. It will also keep the API key secure and prevent CORS problems. Another improvement is to add currency favorites or bookmarks, allowing users to save the currency pairs they use most often. This would make the app more convenient for repeat users.

Other future enhancements include adding multi-language support so users can choose their preferred language. Accessibility improvements can be made, such as better keyboard navigation and more ARIA labels. Offline caching is also a strong possibility: the app could cache recent exchange rates and weather data, allowing it to function even when the network connection is weak. Finally, the user interface can be polished further by adding transitions, better mobile spacing, and more visual cues for interaction.

From this project, I learned a lot about working with API data in a frontend application. I practiced managing application state with `localStorage`, designing responsive layouts, and handling asynchronous fetch requests in JavaScript. I also gained experience with integrating libraries like Chart.js and working around real-world issues like CORS. This project demonstrates both technical skills and thoughtful product design.

As a quick summary, this project is a responsive currency converter with live exchange functionality, a weather panel, a visual trend chart, and a performance-conscious country currency list. It uses local JSON for better performance, stores user preferences in `localStorage`, and is prepared for future backend expansion. The app is structured so that the HTML provides a clean page layout, the CSS handles styling and responsiveness, and the JavaScript manages interactive behavior and data fetching.

In closing, I want to emphasize the practical value of this work. A currency converter is a useful tool for travelers, online shoppers, and anyone who needs to make quick financial decisions across borders. Combining this with local weather information makes the app more relevant and helpful. The project is a good example of how frontend development can deliver a polished experience, even while working within the constraints of public APIs.

If you are interested in the next steps, I would recommend building the backend proxy first and then integrating a richer chart experience. After that, adding features like favorites, offline support, and multi-language would make the product stronger. Thank you for listening. I am now ready to answer questions about the architecture, the APIs, the responsive design, or the planned enhancements.
